ok-player:// link test page (v1, Linux)

Live acceptance for the v1 link contract described in ok-player-links.md. Open this page from disk (file://) in the browser under test; Chromium offers "Always allow" only on https, localhost and file: pages. Each row has one expected result. A build without the v1 link handler answers every row with a "not available yet" notice.

Setup

Create the test clips (60 s each) and the two files that must be refused:

dir="$HOME/Videos/ok-player links"
mkdir -p "$dir"
for name in "a clip" "Café 東京" "take #3"; do
  ffmpeg -hide_banner -loglevel error -y \
    -f lavfi -i "testsrc2=duration=60:size=640x360:rate=30" \
    -f lavfi -i "sine=frequency=440:duration=60" \
    -c:v libx264 -pix_fmt yuv420p -c:a aac -shortest -movflags +faststart \
    "$dir/$name.mp4"
done
printf '#EXTM3U\na clip.mp4\n' > "$dir/list.m3u"
printf '1\n00:00:01,000 --> 00:00:05,000\nHello\n\n' > "$dir/notes.srt"

For the HTTP rows, serve the same folder on the base URL below. Python's built-in server is enough for U1, U3 and Q3, but it ignores Range requests, so U2 cannot seek over it. For U2 use a server that answers Range with 206 Partial Content; check with the second command. 

python3 -m http.server --bind 127.0.0.1 --directory "$HOME/Videos/ok-player links" 8000
curl -s -o /dev/null -w '%{http_code}\n' -H 'Range: bytes=0-1' 'http://127.0.0.1:8000/a%20clip.mp4'

Enter where the clips are; the fixture links below follow. The page keeps both values.

Open local files

Start with OK Player closed for O1. Every accepted open brings the window forward.

IDLinkExpected
O1 open, spaces in folder and file name OK Player starts and plays a clip.mp4; Up Next lists the other clips in the folder.
O2 open, Unicode file name Replaces the current file with Café 東京.mp4; progress of the previous file is saved.
O3 open, # in the file name Plays take #3.mp4 (the # travels as %23).
O4 path form ok-player://open/… Plays take #3.mp4.
O5 + as a space Plays a clip.mp4 (+ in a query value decodes to a space).
O6 opaque form ok-player:open?… Plays Café 東京.mp4.
O7 upper-case action Plays a clip.mp4 (the action is case-insensitive).
O8 url=file:///… Plays take #3.mp4 as a local file, with the folder as Up Next.

Start times

Run each row twice: once with another file playing, once with the same file already current.

IDLinkExpected
T1 t=12.5 (seconds) Plays a clip.mp4 from 0:12.5; if it is already current, seeks there without reloading.
T2 t=0:30 (m:ss) Plays a clip.mp4 from 0:30; if it is already current, seeks without reloading.
T3 t=0:00:45 (h:mm:ss) Plays Café 東京.mp4 from 0:45.
T4 resume=20 (alias of t) Plays take #3.mp4 from 0:20.

HTTP URLs

Needs the HTTP server from the setup section. U2 needs a server that answers Range requests.

IDLinkExpected
U1 http URL with its own query string Streams a clip.mp4; the server log shows the request with ?token=a%2Bb&lang=en intact.
U2 http URL with t=30 Starts Café 東京.mp4 at 0:30 by seeking over Range; no Replay cache download starts.
U3 ok-player://open/?url=… Streams take #3.mp4 (an empty path is not a target).

Queue

Play a clip first and move another window in front of OK Player. add and next must not bring it forward while it plays.

IDLinkExpected
Q1 add while playing Appended to the end of Up Next with a toast; the window stays behind; playback continues.
Q2 next while playing Inserted right after the current item with a toast; the window stays behind.
Q3 add an http URL while playing The HTTP clip is appended to Up Next with a toast.
Q4 add with t=10 Queued; a notice says the start time is ignored for queued items.
Q5 add while idle (close the current file first) Behaves like open: plays Café 東京.mp4 and brings the window forward.
Q6a cold open then add: quit OK Player, click Q6a then Q6b quickly Q6a: plays a clip.mp4.
Q6b (second click of Q6) Up Next holds a clip.mp4 then take #3.mp4, in that order.

Dropped and ignored parameters

IDLinkExpected
P1 unknown keys Plays normally; volume and vf are logged and ignored, never applied.
P2 malformed t Plays as if no start time was given; a notice says the start time was dropped.

Hostile links

Every row must show a rejection toast and leave playback untouched; nothing reaches the engine. A rejected open still brings the window forward (raise depends only on the action).

IDLinkExpected
H1 edl:// target Rejected: only http and https URLs are accepted.
H2 mpv-internal av://lavfi Rejected: mpv-internal protocol.
H3 //host/x path Rejected: a path must start with exactly one /.
H4 //host/x in the path form Rejected: a path must start with exactly one /.
H5 UNC path Rejected: not an absolute local path.
H6 .m3u playlist (the file exists) Rejected: playlist files are not targets in v1.
H7 subtitle file (the file exists) Rejected: subtitle files are not targets in v1.
H8 directory Rejected: not a regular file.
H9 device file Rejected: not a regular file.
H10 missing file Rejected: no such file.
H11 relative path Rejected: not an absolute path.
H12 malformed %G1 Rejected: % not followed by two hex digits.
H13 truncated %2 Rejected: % not followed by two hex digits.
H14 decoded once: %252F Rejected: it names a file literally called a%2Fclip.mp4, which does not exist.
H15 unencoded # Rejected: the link has a fragment.
H16 userinfo in the authority Rejected: the authority must be exactly the action.
H17 port in the authority Rejected: the authority must be exactly the action.
H18 userinfo in the target URL Rejected: @ is not allowed in the URL.
H19 two targets Rejected: exactly one target.
H20 repeated key Rejected: each key at most once.
H21 nested ok-player: Rejected: only http and https URLs are accepted.
H22 URL nested in the path form Rejected: the path form carries local paths only.
H23 file://host/ Rejected: a file URL must have an empty host or localhost.
H24 smb:// Rejected: only http and https URLs are accepted.
H25 unknown action Rejected: the action must be open, add or next.
H26 rejected add while playing Rejection toast; the window stays behind and playback continues.
