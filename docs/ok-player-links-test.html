ok-player:// link test page (v1, Linux)

Live acceptance for the v1 link contract described in ok-player-links.md. Open this page from disk (file://) in the browser under test; Chromium offers "Always allow" only on https, localhost and file: pages. Each row has one expected result. A build without the v1 link handler answers every row with a "not available yet" notice.

Setup

Create the test clips (60 s each, with a tone). The clips in the folder itself show a moving test pattern. The clips under queue/ show colour bars; they are never folder siblings of a playing clip, so queueing them always changes Up Next. The clips under trap/ are solid red: only a link handler that skips a rule ever plays one. list.m3u and notes.srt exist and must still be refused. Keep the folder under your home folder; H11 relies on it. 

dir="$HOME/Videos/ok-player links"
mkdir -p "$dir/queue" "$dir/trap/a"
clip() {  # clip OUTPUT SOURCE: 60 s of a lavfi video source with a tone
  ffmpeg -hide_banner -loglevel error -y -f lavfi -i "$2" \
    -f lavfi -i "sine=frequency=440:duration=60" -t 60 \
    -c:v libx264 -pix_fmt yuv420p -c:a aac -movflags +faststart -f mp4 "$1"
}
for name in "a clip" "Café 東京" "take #3"; do
  clip "$dir/$name.mp4" "testsrc2=size=640x360:rate=30"
done
for name in b c d e; do
  clip "$dir/queue/$name clip.mp4" "smptebars=size=640x360:rate=30"
done
for name in red.mp4 "a%G1.mp4" "a clip.mp4%2" a/clip.mp4; do
  clip "$dir/trap/$name" "color=c=red:size=640x360:rate=30"
done
printf '#EXTM3U\na clip.mp4\n' > "$dir/list.m3u"
printf '1\n00:00:01,000 --> 00:00:05,000\nHello\n\n' > "$dir/notes.srt"

Serve the same folder on the base URL below for the HTTP rows (U1 to U3, Q3) and for H18, H19 and H22. Python's built-in server is enough for all of them except U2: it ignores Range requests, so U2 cannot seek over it. For U2 use a server that answers Range with 206 Partial Content; check with the second command. 

python3 -m http.server --bind 127.0.0.1 --directory "$HOME/Videos/ok-player links" 8000
curl -s -o /dev/null -w '%{http_code}\n' -H 'Range: bytes=0-1' 'http://127.0.0.1:8000/a%20clip.mp4'

Enter where the clips are; the fixture links below follow. The page keeps both values. Under some rows the page also shows the same link as a terminal command. The desktop entry starts the player the same way (ok-player %U), so the command delivers the link exactly as written, with no browser in between.

Open local files

Start with OK Player closed for O1. Every accepted open brings the window forward.

IDLinkExpected
O1 open, spaces in folder and file name OK Player starts and plays a clip.mp4; Up Next lists the three clips of the folder, a clip.mp4 first.
O2 open, Unicode file name Replaces the current file with Café 東京.mp4; progress of the previous file is saved.
O3 open, # in the file name Plays take #3.mp4 (the # travels as %23).
O4 path form ok-player://open/… Plays take #3.mp4.
O5 + as a space Plays a clip.mp4 (+ in a query value decodes to a space).
O6 opaque form ok-player:open?… Plays Café 東京.mp4.
O7 upper-case action Plays a clip.mp4 (the action is case-insensitive).
O8 url=file:///… Plays take #3.mp4 as a local file, with the folder as Up Next.

Start times

Run each row twice: once with another file playing, once with the same file already current.

IDLinkExpected
T1 t=12.5 (seconds) Plays a clip.mp4 from 0:12.5; if it is already current, seeks there without reloading.
T2 t=0:30 (m:ss) Plays a clip.mp4 from 0:30; if it is already current, seeks without reloading.
T3 t=0:00:45 (h:mm:ss) Plays Café 東京.mp4 from 0:45.
T4 resume=20 (alias of t) Plays take #3.mp4 from 0:20.

HTTP URLs

Needs the HTTP server from the setup section. U2 needs a server that answers Range requests.

IDLinkExpected
U1 http URL with its own query string Streams a clip.mp4; the server log shows the request with ?token=a%2Bb&lang=en intact.
U2 http URL with t=30 Starts Café 東京.mp4 at 0:30 by seeking over Range; no Replay cache download starts.
U3 ok-player://open/?url=… Streams take #3.mp4 (an empty path is not a target).

Queue

Before Q1, click O1 so that a clip.mp4 plays and Up Next reads a clip.mp4 (current), Café 東京.mp4, take #3.mp4. Move another window in front of OK Player, then run Q1 to Q5 in order without touching the player. add and next must not bring it forward while it plays. Each expected result lists the whole of Up Next.

IDLinkExpected
Q1 add while playing Toast; the window stays behind and playback continues. Up Next: a clip.mp4 (current), Café 東京.mp4, take #3.mp4, b clip.mp4.
Q2 next while playing Toast; the window stays behind. Up Next: a clip.mp4 (current), c clip.mp4, Café 東京.mp4, take #3.mp4, b clip.mp4.
Q3 add an http URL while playing Toast. Up Next: a clip.mp4 (current), c clip.mp4, Café 東京.mp4, take #3.mp4, b clip.mp4, then the HTTP item d clip.mp4.
Q4 add with t=10 A notice says the start time is ignored for queued items. Up Next: as after Q3, then e clip.mp4.
Q5 add a file that is already queued A toast says it is already in the queue; Up Next does not change.
Q6 add while idle. Close the current media or start OK Player with no file, then move another window in front Behaves like open: the window comes forward and plays Café 東京.mp4; Up Next: a clip.mp4, Café 東京.mp4 (current), take #3.mp4.
Q7a cold open then add. First stop the browser from asking. Click any row and tick Chromium's "Always allow" (offered on this file: page) or Firefox's option to remember the choice. Then quit OK Player and click Q7a and Q7b one right after the other, while the player is still starting Q7a: plays a clip.mp4.
Q7b (second click of Q7) a clip.mp4 plays; Up Next: a clip.mp4 (current), Café 東京.mp4, take #3.mp4, b clip.mp4. No b clip.mp4, or b clip.mp4 playing, means the add was lost or ran before the open.

Dropped and ignored parameters

IDLinkExpected
P1 unknown keys Plays normally; volume and vf are logged and ignored, never applied.
P2 malformed t Plays as if no start time was given; a notice says the start time was dropped.

Hostile links

Unless a row says otherwise, run it with a clip playing. Every row must show a rejection toast and leave playback untouched; nothing reaches the engine.

Every row whose rule could be skipped points at a solid red clip under trap/; H2 asks mpv to draw a red picture instead. If the rule is missing, the link plays red instead of failing on a missing file, so a red picture in this section is always a failure. The only exceptions are H12 and H13 clicked in Chromium; see those rows.

Whether the window comes forward depends on the action and the player state, never on the rejection. A rejected open always comes forward. A rejected add or next comes forward when the player is idle or not running and stays behind while something plays, exactly as an accepted one would (H26 to H28).

IDLinkExpected
H1 edl:// target Rejected: only http and https URLs are accepted.
H2 mpv-internal av://lavfi Rejected: mpv-internal protocol.
H3 //host/… path, here //home/…, which Linux reads as /home/… Rejected: a path must start with exactly one /.
H4 //host/… in the path form Rejected: a path must start with exactly one /.
H5 UNC path Rejected: not an absolute local path.
H6 .m3u playlist (the file exists) Rejected: playlist files are not targets in v1.
H7 subtitle file (the file exists) Rejected: subtitle files are not targets in v1.
H8 directory Rejected: not a regular file.
H9 device file Rejected: not a regular file.
H10 missing file Rejected: no such file.
H11 path relative to your home folder Rejected: not an absolute path. A link's path is never joined to the player's working directory, which is usually your home folder.
H12 malformed %G1, run from a terminal or Firefox Rejected: % not followed by two hex digits. In Chromium this row proves nothing. Chromium rewrites %G1 to %25G1 before launching, so the player correctly plays the red trap/a%G1.mp4.
H13 truncated %2, run from a terminal or Firefox Rejected: % not followed by two hex digits. In Chromium this row proves nothing. Chromium rewrites the trailing %2 to %252, so the player correctly plays the red trap/a clip.mp4%2.
H14 decoded once: %252F Rejected: decoded once, it names trap/a%2Fclip.mp4, which does not exist. The red trap/a/clip.mp4 plays only if the value is decoded twice.
H15 unencoded # Rejected: the link has a fragment.
H16 userinfo in the authority Rejected: the authority must be exactly the action.
H17 port in the authority Rejected: the authority must be exactly the action.
H18 userinfo in the target URL Rejected: @ is not allowed in the URL.
H19 two targets Rejected: exactly one target.
H20 repeated key Rejected: each key at most once.
H21 nested ok-player: Rejected: only http and https URLs are accepted.
H22 URL nested in the path form Rejected: the path form carries local paths only.
H23 file://host/ Rejected: a file URL must have an empty host or localhost.
H24 smb:// Rejected: only http and https URLs are accepted.
H25 unknown action Rejected: the action must be open, add or next.
H26 rejected add while playing, another window in front Rejection toast; the window stays behind and playback continues, as for an accepted add (Q1).
H27 rejected add while idle. Close the current media, then move another window in front The window comes forward with a rejection toast, exactly as for an accepted add while idle (Q6). Staying behind would tell a page that the file does not exist.
H28 rejected next with OK Player not running OK Player starts; its window opens idle with a rejection toast.
